# 采集方法与结构

拾藏将“从网站读取”和“管理自己的收藏”分开。用户主动打开已登录页面，浏览器扩展从DOM读取内容卡片，累计去重后展示预览，经用户确认才提交给本机服务。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `extension/panel.js` | 扫描控制、X解析、预览和API通信 |
| `extension/adapters.js` | 抖音、知乎的DOM解析及滚动/翻页 |
| `extension/theme.js` | 采集面板主题偏好 |
| `server.py` | 回环HTTP服务、连接认证、请求和来源校验 |
| `store.py` | URL规范化、来源校验、SQLite入库与合并 |
| `web/` | 本地搜索、筛选、卡片、标签和备注 |

## 平台适配

- X读取`article[data-testid="tweet"]`中的原帖链接、作者、正文和封面；历史页区分书签/喜欢。
- 抖音确认个人页选中的收藏/喜欢标签，读取`/video/ID`和`/note/ID`链接，滚动包含视频卡片的内部容器。
- 知乎只在具体收藏夹读取`.ContentItem`中的回答、文章、想法和视频链接，自动读取名称并点击下一页。翻页后等待内容变化。

适配器只读取当前用户可访问的页面，不绕过验证码，不提取会话凭据，不直接下载图片、视频或正文。页面选择器不是平台稳定API，站点改版后需要维护。

## 去重与合并

记录保留`platform`、`source_id`、`canonical_url`、`source_types`、可见内容字段和用户管理字段。

- X帖子ID去除追踪参数；抖音视频/图文按作品ID去重；知乎区分回答、文章、想法和视频ID。
- 数据库存储键带平台命名空间，避免不同站点相同数字ID碰撞；X早期存储键兼容保留。
- 重复导入合并来源类型，刷新可确认的来源字段，保留标签、备注和已看状态。
- 某条记录未在新扫描中出现，不自动删除本地历史。

## 本地接口

请求通过`X-Collection-Token`发送本机连接密钥。

| 接口 | 用途 |
| --- | --- |
| `GET /api/bookmarks` | 列出记录 |
| `POST /api/preview` | 预览新增、已有和无效数量 |
| `POST /api/import` | 提交`{"items": [...], "mode": "manual"}` |
| `PATCH /api/bookmarks/ID` | 编辑标签、备注和已看状态 |
| `GET /api/history` | 最近导入批次 |
| `GET /api/export` | 导出记录JSON |

接口只在本机使用，不是经过公网部署审计的多用户服务。

## 增加一个平台

先在真实已登录页面确认链接、内容标识、所属标签和翻页方式，再将读取逻辑集中到适配器。同步增加服务端URL/封面域名校验、平台命名空间、网页筛选及测试。先验证小样本、错误页面拒绝、重复导入与用户字段保护，再扩大扫描范围。

当前主要限制是页面加载与可见性，不能用轮数、没有新增或网站的总数替代覆盖证明。
